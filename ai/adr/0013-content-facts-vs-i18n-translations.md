# 0013 - Split content into facts and translations; retire check-locales.ts

**Context.** The first implementation had `content/en/*.ts` and
`content/pt/*.ts`, each a full duplicate array per collection. Only the
prose fields actually differed between locales - dates, hrefs, stack
arrays, and image dimensions were identical, hand-copied text. A
`scripts/check-locales.ts` runtime script existed solely to catch a locale
falling out of sync.

**Decision.** Collections now live once, locale-independent, in
`src/content/*.ts`. Translatable prose moved into `src/i18n/locales/
{en,pt}.ts` under a `content` key, typed as `Record<ExactIdUnion,
Translation>` (see ADR 0004). `content/index.ts`'s `useContent()` merges the
two per the active locale. `scripts/check-locales.ts` was deleted.

**Consequences.** No more duplicated facts - a date or a stack array is
edited once. The compiler now enforces translation parity more strictly
than the runtime script did: a missing PT entry is a `vue-tsc` error at the
exact locale file and key, not a report generated by remembering to run a
separate script. The cost is one extra required edit when adding a new
collection entry - the id must be added to the relevant union in
`content/types.ts` before either the fact array or the translation maps
will type-check against it. See `ai/cookbook.md` for the exact steps.
